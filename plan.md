# Личные финансы: учёт капитала

Персональный сервис одного человека: учёт активов разных типов и валют, исторические
курсы, аналитика роста. Архитектура — **толстый TUI-клиент + PostgreSQL как ядро**.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Форма | Консольное приложение: бинарь `finance` (Go, bubbletea TUI) |
| Архитектура | Толстый клиент: TUI работает с PostgreSQL напрямую, без HTTP-сервера |
| Ядро | PostgreSQL: данные + расчёты в SQL (вьюхи, функции) — смена клиента не переносит логику |
| Фоновые джобы | Режим того же бинаря: `finance jobs` (крон на домашнем сервере) — курсы, материализация правил |
| БД | PostgreSQL на домашней инфре, наружу не торчит (LAN/Tailscale) |
| Деньги | numeric(38,12) в PG, decimal в Go |
| Веб-прототип M1 | Ветка `m1` (Next.js) — заархивирован, служит спецификацией контракта и схемы |

## Архитектура

```
┌─────────────────┐         ┌──────────────────────────────┐
│ finance (TUI)   │─────────▶  PostgreSQL                  │
│ рендер + ввод   │  TCP    │  таблицы, вьюхи, функции     │
└─────────────────┘         │  = ядро и калькулятор        │
┌─────────────────┐         └──────────────────────────────┘
│ finance jobs    │─────────▶ (cron на сервере: курсы, правила)
└─────────────────┘
```

- **Клиент** — рендер + калькулятор отображения + запись значений. Бизнес-расчёты
  (стоимость актива на дату, портфель, разложение роста) живут в SQL-вьюхах и функциях.
- **Джобы** — материализация правил и загрузка курсов; правила материализуются
  SQL-функцией `materialize_recurring_rules(as_of)`, её позвают и джоба, и клиент на старте.
- **Снепшоты** — сначала без таблицы: series считается вьюхой на лету (объёмы маленькие);
  materialized view, если станет медленно.

## Доменная модель

Три слоя, как и раньше: количество × цена единицы × курс.

- **Количество** меняется только операциями (`operation`, событийная модель).
- **Цена единицы**: ликвидные активы — из `price`; недвижимость/вручную — из
  `revaluation` (последняя ≤ даты); invested — выводится из вложений.
- **Курс**: единая таблица `price` (unit, in_unit, on_date), конвертация через граф пар.
- **Квартира с ипотекой** (`valuation='invested'`): стоимость = взнос + погашенное тело;
  рыночная оценка — справочная линия (`revaluation.kind='market'`), в капитал не входит.

## Схема БД

`asset`, `operation`, `revaluation`, `price`, `recurring_rule`, `settings` — те же
таблицы, что в веб-прототипе (см. ветку `m1`), плюс вьюха `asset_summary` (количество
и вложения по активу) и функция `materialize_recurring_rules(as_of date)` с клампом
на последний день короткого месяца.

## Стек

Go 1.27, bubbletea/bubbles/lipgloss (TUI), pgx v5 (PostgreSQL), встроенные SQL-миграции.
Конфиг: `FINANCE_DB` (строка подключения), дефолт — локальная PG.

## Вехи

1. **M1 Каркас** — миграции схемы, `finance migrate`, TUI-список активов, ввод актива.
2. **M2 Учёт** — операции и переоценки (ввод/удаление), правила автообновления + джоба.
3. **M3 Курсы** — провайдеры (НБ РК, ЦБ РФ, крипта), `finance jobs`, вьюхи стоимости,
   конвертация и переключение валюты отображения.
4. **M4 Аналитика** — графики в терминале, разложение роста (SQL-функция), полировка.
